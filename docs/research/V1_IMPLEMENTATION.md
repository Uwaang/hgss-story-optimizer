# 현실성 명세 v1 구현 계획

기준: [CHARTER.md](CHARTER.md)의 현실성 명세 v1 중 신규·수정 항목 3개. 이 세 가지가 끝나고 사용자가 v1을 고정하기 전에는 파티 탐색을 시작하지 않는다.

## 1. 노가다 계획에 경험치 받는 멤버를 넣기

현재: `grindPolicy === 'planned'`은 체크포인트별 노가다 전투 수만 받고, 경험치는 `allocateTrackedGrind()`가 고정 분배 규칙(`boss-aware-soft` 등)으로 나눈다 (`exp-budget.mjs` 1553, 1828–1855행). 이 규칙이 유용한 멤버에게 몰아준다.

변경:

- 노가다 계획 형식을 `{체크포인트: {멤버 키: 전투 수}}`로 넓힌다. 멤버를 지정한 노가다는 분배 규칙을 거치지 않고 그 멤버에게 바로 간다.
- 4세대 경험치 공식은 받는 쪽 레벨에 따라 줄지 않으므로, 전투당 경험치는 장소의 기댓값(`wild.expectedExpPerBattle`) 그대로 쓴다.
- 기존 형식(`{체크포인트: 전투 수}`)은 이전 실험 재현용으로 그대로 둔다.
- 레벨 변동계수는 같은 평가 결과에서 사천왕 1차·2차·Red 진입 레벨로 계산한다 (비교 축 모듈 한 곳).

상태 (2026-10-18): 구현됨. `src/comparison-axes.mjs`(비교 축 모듈)와 `grindPlanBattles`의 멤버 지정 형식, 검사 `npm run comparison-axes-smoke`. 기존 EXP 검사 4개(segment, allocator, scheduler-v1, budget) 통과.

결정 (2026-10-18, 사용자 확정): 체크포인트에 아직 합류하지 않은 멤버는 레벨 0으로 계산한다. 그래서 사천왕에 멤버가 적게 들어가면 쏠린 파티로 읽힌다. 합류 멤버 수는 `members` 값으로 함께 남는다.

## 2. 사천왕 사이 회복을 가방 아이템 비용으로 세기

현재: 사천왕 5연전은 사이 회복을 무료로 가정한다 (`cli.mjs` 17573–17586, 17905–17926행 `betweenBattles`, `bagInBattle: 'forbidden'`).

변경 (v1):

- 클리어 확률 계산 방식은 그대로 둔다. 사이에 가득 회복한다는 가정을 유지한다.
- 각 전투가 끝난 상태(남은 HP, 기절 수, 상태이상)에서 가득 회복하는 데 필요한 아이템 수를 정해진 규칙으로 계산해 사용량에 더한다.
- 그 규칙은 미결 사항(아이템 사용 규칙)과 같은 것으로, 사용자가 정한다.

## 3. 전투 중 플레이어의 가방 아이템 사용

현재: 상대 트레이너만 회복약을 쓴다 (`chooseHgssTrainerItem`, `applyHgssTrainerItemTurn`, `battle.mjs` 1774–1802, 2303–2309행). 플레이어 쪽은 기술·교체만 고른다.

변경:

- 같은 아이템 사용 처리(한 턴 소모)를 플레이어 쪽에도 연결한다.
- 언제 쓸지는 고정된 한 가지 규칙으로 정한다 (미결 사항, 사용자 결정).
- 보유 수량은 그 시점까지의 상점 입수와 소지금으로 제한하고, 사용 개수를 전투 결과에 남긴다.

## 순서와 검증

1. 비교 축 계산 모듈 하나 (노가다 전투 수, 재도전, 변동계수, 아이템 사용량) — 모든 스크립트가 이것만 쓴다.
2. 항목 1 → 2 → 3 순서로 구현. 각 항목은 작은 검사(smoke)로 기존 결과가 기존 형식에서 그대로 재현되는지 확인한다.
3. 사용자가 미결 사항을 정하고 v1을 고정한다.
4. 그 뒤 CHARTER.md의 고정 절차대로 탐색을 한 번 실행한다.
